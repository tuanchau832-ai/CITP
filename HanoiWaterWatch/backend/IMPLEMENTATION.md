# Backend implementation

The backend is a one-worker FastAPI application with durable SQLAlchemy persistence. The deployment driver is psycopg 3 against PostgreSQL; `postgresql+asyncpg` environment URLs are normalized to the synchronous driver. SQLite is supported for development and tests. Start with `uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000 --workers 1` from backend, with DATABASE_URL and a JWT_SECRET of at least 32 characters set.

Run `alembic -c backend/alembic.ini upgrade head` from the repository root, then (with backend on PYTHONPATH) `python -m app.cli seed`. Demo users come exclusively from DEMO_OPERATOR_USERNAME/PASSWORD, DEMO_REVIEWER_USERNAME/PASSWORD and DEMO_ADMIN_USERNAME/PASSWORD. Rotate the Wokwi key with `python -m app.cli devices rotate-key wokwi-esp32-01`; the raw key is returned once, only its SHA-256 is persisted. Never commit the printed key. COOKIE_SECURE defaults true; local HTTP development requires explicit false.

Implemented behavior includes strict device ingest, body limits and per-key/IP token buckets; bound hashed keys; server-derived simulated provenance; atomic validated batches; frame idempotency; station row locking; durable sessions and persistence counters; all six rules with session-scoped, frozen change baselines; null live values for faults/offline/unavailable; out-of-order live-state protection; snapshots and ETags; history aggregation, timeline, diagnostics; argon2 passwords and HttpOnly JWT cookie roles/CSRF; alert acknowledgement, private notes and incident reviews; impossible verified outcomes prevented at service and database layers; configurable rule updates and key rotation; replay catalog/takeover/scaled timing/stop/TLH loop; daily retention at 03:00 ICT; demo reset; built frontend serving with safe history fallback.

Verification: tests were written first and initially failed to import the absent application. Further regression tests exposed and fixed backfill status rewind and a missing replay catalog import. Material implementation choices and limits:

- Synchronous SQLAlchemy services replace the blueprint asyncpg stack. Ingest and the monitor use thread offloading; one process-wide reentrant lock and PostgreSQL `FOR UPDATE` serialize station changes, and snapshot reads use that same lock. One worker is mandatory. SQL is currently colocated with route handlers for some read/review operations rather than fully split into the proposed service modules.
- Registry metadata is stored on station JSON/JSONB rows; station/device/sensor identifiers are natural keys rather than a separate internal bigint identity for every catalogue table. Measurements, events, reviews and alerts use generated integer identities. Timestamps use real PostgreSQL timezone-aware DateTime columns, exposed through a UTC serialization type. SQLite behavior is the locally verified database evidence; no running PostgreSQL/Docker instance was available.
- Backfilled readings use separate persisted rule counters. Historical episodes carry `detected_late` and clear when subsequent measured evidence meets the rule's recovery condition. The live sensor status and its active-alert pointer come from the live rule counters.
- History bucketing uses equivalent UTC grouping in Python so SQLite and PostgreSQL give the same output. This is suitable for the seven-day demonstration window but does not implement PostgreSQL date_bin query pushdown; large deployments need that optimization. Pagination uses offsets rather than keyset cursors.
- SSE is deliberately disabled (the blueprint marks this MVP+); `/stream` returns an explicit problem response and metadata advertises false. Polling is fully supported.
- Replay scheduling and freshness are process tasks; interrupted runs do not resume on process restart. Sessions are durable, idle expiry releases them, and the configured TLH loop takes over cleanly at startup. Deployment migrations must run before application startup when upgrading an existing database.
- Authentication failure diagnostics and rate buckets are in memory, as specified for one worker. Logout clears the cookie; already copied JWTs remain valid until expiry.
- Station model and public Wokwi execution were not verified here. All API data remains explicitly simulated and reference regulatory text stays unverified by default.
