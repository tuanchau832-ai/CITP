# Hanoi WaterWatch Implementation Plan

> **For agentic workers:** Use the blueprint as the binding specification and test behavior before implementation. User authorised direct implementation and routine decisions on 18 November 2026.

**Goal:** Build the documented full-stack simulated monitoring platform in this repository.

**Architecture:** FastAPI owns ingest, persisted state, rules and alert review. React consumes one versioned station snapshot through TanStack Query. Firmware and replay use the same frame contract; PostgreSQL is the deployed database.

**Tech Stack:** React 19, TypeScript, Vite, Leaflet, React Three Fiber, Recharts, FastAPI, SQLAlchemy, Alembic, PostgreSQL 16, Arduino ESP32.

**Spec:** `docs/blueprint/README.md` and numbered sections 01–11.

## Global Constraints

- All data is simulated; provenance is server assigned. Every data screen shows the fixed simulated-data notice.
- Station codes, channels, units and GPIO mappings follow blueprint 05. No frontend threshold computation.
- Fault, offline and unavailable current values are null. Prior valid values are separate.
- Snapshot versions increase, retries are idempotent, back-fill cannot rewind live values.
- Staff actions require server authorisation. Simulated alerts can never become verified incidents.
- User supplies station model; missing model renders the accessible 2D fallback and is reported honestly.

## Review Focus

- Duplicate and out-of-order frames must not corrupt the current snapshot.
- Invalid units and forged provenance must fail before writes.
- Offline and API disconnect must not show old numbers as live.
- Anonymous visitors must not see staff notes or execute mutations.
- Missing model and map tiles must leave usable sensor and station lists.
